# 100k text/PDF manifest — build notes

Generated by [scripts/build_manifest.py](../scripts/build_manifest.py) into
`/run/media/me/D/ML_DS/UVTM/Layouts/test/text_pdf_manifest.csv` (100,000 rows, columns:
`id,category,source_dataset,format,file,page,lang,seed,note`). Generated data (CSV, rendered
samples) lives under `Layouts/test/`, not in this repo, per instruction. `file` is relative to
`/run/media/me/D/ML_DS/UVTM/Layouts`; for DocLayNet rows it's `<shard>.parquet::row<idx>`.

`format=text_extracted` rows store no text inline — `seed` fixes a reproducible font/size/layout
choice, and the cleaned text itself is re-derived at render time from the source (PDF page or
`Texts/*.txt` file) via [scripts/text_extract.py](../scripts/text_extract.py), so the CSV stays
small and rendering is deterministic from `(file, page, seed)` alone.

## Round 2 fixes (this revision)

1. **Tofu boxes on ~20% of text_extracted pages** — the font was picked from one general Latin
   pool regardless of the text's actual script, so Bengali/Arabic/Hebrew/CJK/Urdu text drew as
   empty glyph boxes. Fixed in [scripts/text_fonts.py](../scripts/text_fonts.py): each row's
   `lang` now routes to a script-appropriate Noto font (Arabic, Hebrew, Devanagari, Bengali,
   Thai, per-face CJK via `.ttc` index, Nastaliq for Urdu/Persian) before falling back to the
   20-font Latin/Cyrillic/Greek pool. Arabic/Urdu additionally get real letter-joining +
   right-to-left reordering (`arabic-reshaper` + `python-bidi`), not just correct glyphs.
   - A second, different-looking artifact turned up during this fix on one Bengali PDF: dotted-
     circle placeholders (a real Unicode "orphan combining mark" indicator) scattered through
     the text. Root cause wasn't the renderer — that PDF's embedded font maps some glyphs onto
     raw C0/C1 control code points instead of real Unicode, so extraction pulls back literal
     control characters. There's no way to recover the intended character from a broken cmap, so
     `text_extract.py` now measures the control-character ratio per page and returns `""` (falls
     back to native PDF rendering) above `CONTROL_CHAR_CORRUPTION_RATIO` (0.5%) instead of
     rendering a text full of garbage.
   - A third, genuinely-tofu case surfaced in the same review: a watermark line embedded a bare
     URL (`www.amarboi.com`) inside otherwise-Bengali text, and the Bengali font has no Latin
     glyphs for it. Handled as part of fix 2 below (the line is a watermark and gets dropped
     outright), not by adding per-run font-switching for arbitrary mixed-script lines.
2. **pleias_multilang dropped** (flagged low quality) and replaced by two sources: `Texts/`
   (parallel classic-novel translations — used now, unlike round 1, where it was left out) and
   real text extracted from `books/*.pdf` itself (including books added since round 1). Every
   `books/*.pdf` and `textbook/*.pdf` page now gets `format=text_extracted` when it clears a
   200-char real-text floor, else falls back to `format=pdf` (native raster) for scanned/
   image-only pages — so the same book can mix both depending on the page.
3. **OceanofPDF.com watermark + false newlines**, and (found along the way) a second piracy-site
   watermark pattern (bare domain lines like `amarboi.com`, `www.amarboi.com`) — both stripped in
   [scripts/text_extract.py](../scripts/text_extract.py). False newlines (PDF/plain-text hard-wrap
   at the visual line, not the paragraph, producing a mid-sentence break every ~60-90 chars) are
   fixed by treating PyMuPDF's layout `blocks` (PDFs) or blank-line runs (`Texts/`) as the real
   paragraph boundary, dehyphenating word-wrap breaks, and joining every other newline back into
   running prose.
4. **Font/size/margin/alignment variety**: [scripts/build_textures.py](../scripts/build_textures.py)
   draws each text page with one of 20 pool fonts (script-routed via
   [scripts/text_fonts.py](../scripts/text_fonts.py)), 8-16pt size, 1.15-1.4x line spacing,
   left/right/justify alignment, and 0-5% independent per-side margins, all deterministic from
   the row's stable seed. Glyph rasterization and compositing go through
   [scripts/glyph_render.py](../scripts/glyph_render.py) (cached glyph bitmaps/widths, single
   batched numba blit per page) rather than per-call PIL drawing.

## Decisions and why (carried over from round 1, still true)

- **Archive/ untouched.** Rules out the quota doc's reference_encyclopedia/Wiktionary-dictionary
  rows — their only local source is `Archive/reference_dictionary.7z`.
- **`classification_table.csv` is stale** (references a directory layout that no longer exists) —
  the manifest is built from the actual current files, not from that CSV.
- **RVL-CDIP excluded**: sampled images measured ~754–808 × 1000 px, under the 1024×1024 floor.
- **DocLayNet-v1.2** used in full, split by `metadata.doc_category`.
- **books/ technical vs non-technical** split by filename marker list (now 5 technical titles,
  up from 2, after new books were added). `the_penguin_dictionary_of_jokes.pdf` goes to
  `dictionary`, not fiction. `The_mathematical_experience_-_Philip_J_Davis.pdf` and
  `dictionares/Larousse_Concise_Dictionary_-_Larousse.pdf` still fail to open (corrupt).
- **Quota-doc rows with no local, non-Archive source** (checks, healthcare forms, invoice/receipt
  as a distinct class, correspondence, handwritten tables, exam/worksheets) remain unfilled.
- Resolution: PDF pages render at a zoom chosen from `max(long-edge target, 1024/short-edge)` so
  narrow-aspect pages (e.g. 998×1601 native) still clear 1024px on both sides, not just the long
  edge — round 1's zoom formula missed this for one dictionary sample.
- Text-density (>30% ink) is still not enforced at manifest-build time (it's a raster-time
  property) — unchanged follow-up from round 1.
